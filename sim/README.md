# Проверка FIR-фильтра

Python готовит входные данные и ожидаемые результаты. Тестбенч проверяет
задержку конвейера и сравнивает выход FIR с эталоном.

## Запуск

Нужны Python 3 и Icarus Verilog (`iverilog`, `vvp`). Сторонние Python-пакеты
не требуются. Команды выполнять из корня проекта:

```bash
python3 sim/test_fir.py
iverilog -g2012 -I sim/build -s tb_test -o sim/build/tb_test.vvp rtl/fir_filter.v sim/tb_test.sv
vvp sim/build/tb_test.vvp
```

При каждом запуске `vvp` тестбенч записывает временную диаграмму
`sim/build/tb_test.vcd`. Чтобы открыть её в GTKWave, выполните команду ниже.

```bash
gtkwave sim/build/tb_test.vcd
```

При ошибке TB завершает симуляцию через `$fatal(1, ...)`, возвращая
ненулевой код завершения.
Python создаёт данные; компиляция и симуляция запускаются отдельно.

## Параметры

По умолчанию используются параметры RTL: `X_WIDTH=14`, `H_WIDTH=14`,
`TAPS=15`, все `PIPE_*=1`, 200 входных отсчётов и `seed=42`.
Коэффициенты задаются в `DEFAULT_COEFFS` скрипта. Это тестовый набор с
усилением больше единицы, чтобы проверить насыщение обоих знаков.
В RTL встроенных коэффициентов нет.

Пример проверки округления с одним отводом и коэффициентом `0.5`:

```bash
python3 sim/test_fir.py --coeffs 4096 --pipe-mul 0 --pipe-sum 0 --pipe-round 0
iverilog -g2012 -I sim/build -s tb_test -o sim/build/tb_test.vvp rtl/fir_filter.v sim/tb_test.sv
vvp sim/build/tb_test.vvp
```

Опции `--x-width`, `--h-width`, `--coeffs`, `--pipe-mul`, `--pipe-sum`,
`--pipe-round`, `--num-samples`, `--seed` меняют конфигурацию.
`--coeffs` принимает signed-коды в порядке `h_0, h_1, ...`; их количество
задаёт `TAPS`. Все коды должны помещаться в `H_WIDTH` бит.
При уменьшении `H_WIDTH` при необходимости задайте новый набор коэффициентов.
Короткий запуск через `--num-samples` обрезает последовательность тестов.

После генерации нужно заново компилировать TB: он включает созданный
`tb_params.vh`, чтобы параметры DUT совпадали с моделью.
Для другого каталога используйте `--outdir sim/build/custom`,
`-I sim/build/custom` при компиляции и `+DATA_DIR=sim/build/custom` при запуске.
Диаграмма `tb_test.vcd` сохраняется в том же каталоге.

Чтобы повторить прогон с симметричным набором коэффициентов, сгенерируйте
данные этой командой и выполните обычную компиляцию и запуск TB.

```bash
python3 sim/test_fir.py --num-samples 200 --seed 42 \
  --coeffs 128 256 512 768 1024 1536 2048 2304 2048 1536 1024 768 512 256 128
```

## Файлы и проверка

Все генерируемые файлы по умолчанию лежат в `sim/build/`:

| Файл | Содержимое |
| --- | --- |
| `tb_params.vh` | Разрядности, число отводов и параметры конвейера |
| `coefficients.txt` | Один signed-код коэффициента на строку, начиная с `h_0` |
| `input_stimulus.txt` | Одна строка `rst ce x` на физический такт |
| `expected_output.txt` | Математический результат для каждой строки входа, до задержки конвейера |

Для строк со сбросом или `ce=0` эталон содержит ноль-заполнитель, который
не загружается в массив задержки. Коэффициенты постоянны в течение запуска.
Python считает сумму целыми числами, округляет к ближайшему с половинами
к чётному и ограничивает результат диапазоном `X_WIDTH`.

TB подаёт входы по отрицательному фронту и проверяет выход через 1 нс после
положительного фронта, когда выполнены неблокирующие присваивания RTL.
Массив `expected_pipeline` содержит `PIPE_STAGES` элементов:

```text
При PIPE_*=1:
E0: [Y0,  0,  0,  0]  y_valid=0
E1: [Y1, Y0,  0,  0]  y_valid=0
E2: [Y2, Y1, Y0,  0]  y_valid=0
E3: [Y3, Y2, Y1, Y0]  y_valid=1, y=Y0
```

`E0...E3` — только разрешённые фронты. При `ce=0` массив, ожидаемые `y`
и `y_valid` удерживаются; такой выход повторно не считается. При `rst=1`
массив очищается независимо от `ce`. Сравнение охватывает также нулевой
выход после сброса и во время заполнения конвейера.

Сценарий включает импульс, положительную и отрицательную ступени, граничные
и случайные значения, паузы с изменяющимся `x`, а также сброс в середине
потока при обоих значениях `ce`. После конца файла TB подаёт ещё `LATENCY`
нулевых входов, чтобы проверить все оставшиеся результаты из файла.

Сброс намеренно отменяет ещё не вышедшие результаты. Они учитываются
отдельно; TB проверяет равенство `accepted = checked + discarded`.
Поэтому стандартный запуск заканчивается так:

```text
[TB] RESULT : PASS (197 outputs matched, 3 pending results discarded by reset)
```

## Выполненные проверки

В Icarus успешно проверены 48 конфигураций: все восемь комбинаций `PIPE_*`
для каждого из шести наборов — стандартного, одного отвода с коэффициентом
`0.5`, асимметричного набора со знаками, `H_WIDTH=1`, однобитного входа и
коэффициента, а также `X_WIDTH=48, H_WIDTH=40`.
Эталон дополнительно сверялся с независимым расчётом через `fractions.Fraction`.
Намеренное искажение последнего проверяемого результата, пустой и повреждённый
входные файлы приводили к ненулевому коду завершения симулятора.
